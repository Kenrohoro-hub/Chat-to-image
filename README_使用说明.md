# Chat to image 使用说明

Chat to image 的详细操作说明。项目概览、源码启动和当前使用限制见 [仓库首页](README.md)；开发状态和验收范围以 [开发大纲](tasks/plan.md) 为准。

## 功能介绍

启动时自动显示功能介绍，可勾选 **不再自动显示此介绍** 后点击 **开始使用** 永久关闭自动弹出（当前桌面或浏览器入口记忆，清理本地存储后会重置）。以后仍可进入 **设置与 API → 功能介绍**，查看 Chat to image 的版本、主要功能和开始使用步骤。项目地址为 [Kenrohoro-hub/Chat-to-image](https://github.com/Kenrohoro-hub/Chat-to-image)。当前独立版本为 **0.1.0**。

## 启动

1. 双击项目根目录的 **run-app.cmd**。
2. 首次需要 Python 3.10+；启动器在本机用户目录建立专用 Python 运行环境，自动安装 `requirements-desktop.txt` 声明的桌面组件，需要联网。首次准备可能耗时，完成后打开窗口；失败显示 Windows 错误提示。窗口使用 Windows WebView2。
3. 出现独立 **Chat to image** 窗口。正常运行不保留 CMD 窗口；启动前的错误会保留提示。
4. 点击左下角 **设置与 API**，填写服务地址、Key 和模型。已有的有效网页同步配置会在首次桌面启动时导入。

源码或构建文件更新后，先关闭工具，再双击 **build-app.cmd**。它在当前电脑的缓存目录构建，再更新项目的 `dist/`，支持网络共享路径。运行已构建桌面不需要 Node；重新构建需要 Node/npm。

## 界面与生图

| 入口 | 操作 |
| --- | --- |
| 创作 | 左侧显示创作对话，输入框固定在底部；右侧比较当前对话分支各轮图片，底部显示最近生成 |
| 对话式创作 | 默认可以讨论构图、光线和提示词；明确说“生成一张…”或“修改这张…”时再出图。对话使用 Responses API，图片使用 Images API |
| 只优化提示词 | 仅请求文字，关闭本轮生图工具；回复下点击“填入输入框”继续修改，或“按此提示词生图”明确提交 |
| 直接生成 | 将输入的提示词和附件直接交给 Images API，不经过对话模型；只有图像配置也能使用 |
| 操作指南 | 点击顶部“操作指南”，按主题查看开始配置、对话与直接生成、图片编辑、对话管理、历史收藏、提示词和备份说明；支持键盘操作及窄屏浏览 |
| 提示词与参考图 | “提示词库”可保存、编辑、搜索个人提示词，默认提供三个可编辑、可删除的展示示例；上传、拖入、粘贴或从结果和历史添加参考图，附件缩略图可移除，输入 `@` 指定图片 |
| 生图参数 | 顶部“生图参数”打开抽屉，展示图像模型、质量、尺寸、比例、透明背景、格式、压缩、审核和张数；图像参数按对话保存。对话模型、推理强度和联网在输入工具栏 |
| 结果比较 | 右侧并排展示当前对话分支的各轮图片，不混入其他分支或对话；显示完成/目标张数、轮次、模型和尺寸，失败提示独立保留。点选图片后使用底部操作，默认选中最新图片；完整提示词、方案、耗时和实际参数在“提示词与详情”中 |
| 连续修改 | 先点选要修改的图片，再点击底部“继续修改”，将所选图作为附件并回到输入框；“蒙版编辑”打开现有蒙版工具，还可下载、放大、复用参数或收藏。生成期间禁止修改草稿类操作 |
| 最近生成 | 右侧底部横向展示全局最近 20 个任务的缩略图，最新在前。点击缩略图预览，“展开操作”或顶部“最近生成”打开完整历史，可加入参考、复用、查看详情或删除；删除需确认，生成中的任务需先停止。浏览不切换对话、不覆盖比较区、不自动提交 |
| 历史详情 | 图片按比例完整显示，参数区独立纵向滚动，底部操作始终可见；按钮风格统一，长文字可换成两行。质量、审核和透明背景显示中文，宽高比随当前图片更新，长参数与来源换行显示 |
| 对话与作品管理 | 创作页顶部“对话历史”打开完整列表，“新建对话”创建空白对话；列表可搜索标题和正文，单条对话可改名或删除，也可进入“多选”后批量删除。“全选”只选择当前搜索结果。运行中的条目标为“生图中”或“回复中”，确认删除时会跳过并提示；其余已选对话可继续删除。默认删除对话并保留作品，可勾选同时删除关联任务和图片。切换对话恢复各自草稿；内置示例只在历史和收藏中展示，新对话的当前结果为空 |
| 窄屏 | 使用“对话 / 聚焦图片”切换主要区域，避免左右栏挤压；选择图片继续修改会自动返回对话，草稿保留。参数与最近生成仍可通过抽屉访问，支持 Escape 关闭和键盘操作 |

创作区默认采用 **左侧对话、右侧多图比较**，输入框固定在对话栏底部，最近生成缩略图位于比较区底部。顶部 **对话历史** 打开对话列表，**新建对话** 开始空白创作；**左右分栏 / 展开对话 / 聚焦图片** 可调整工作视图。点击 **生图参数** 或 **最近生成** 打开抽屉，关闭再打开保留已编辑参数。

在对话列表中点击 **多选**，可勾选单条对话或全选当前搜索结果，再点击 **删除所选** 并确认。列表会显示正在生图或回复的对话；批量删除时这些对话会被保留并提示，其他可删除项仍会处理。删除默认只删除对话；确认弹窗中勾选 **同时删除关联任务和图片** 才会一并删除作品及生成记录。

输入框采用紧凑布局，多行文字会自动增高；发送快捷键可在“发送”按钮的悬停提示中查看。提交后提示词和附件进入对话记录，输入框清空以便开始下一轮。历史复用填入提示词、参数、参考图及有效蒙版，使用生图参数中当前所选图像服务，并提供一次撤销；可继续调整后再提交。

## 动态 API 主备配置

在“设置与 API → API 配置”中，先选择用途：

| 分组 | 接口及参数 | 主备范围 |
| --- | --- | --- |
| 画廊 · Images | Images 接口备注说明；填写地址、Key、图像模型，按服务需要设置 Base64 返回等参数 | 每组最多 10 套，桌面同步 Images 与 Codex 直接调用共用 |
| Agent · Responses | Responses 接口备注说明；填写地址、Key、可选对话模型列表，可设置文字流式返回；推理强度在对话输入区选择 | 每组最多 10 套，供 Agent 对话和标题使用，支持文字流式；图片执行归画廊 |

两组的主用、启停、备用顺序和自动切换开关互不影响。

1. 点击 **添加 API 配置**，只显示实际配置行。每组最多 10 套，停用也计数；满额后添加和复制不可用，删除后恢复。导入超限会明确拒绝，已有数据不被静默截断。
2. 点配置行展开编辑卡，填写名称、地址、Key 和模型。编辑与主用选择分开，切换配置或分组保留本次草稿。
3. 点击 **设为主用**，使用复选框启停方案；上箭头调整备用顺序。主用停用时，开启自动切换才会尝试启用的备用。
4. 明确点击 **保存配置** 后生效；顶部和编辑卡均有保存/取消入口。取消会放弃本次全部未保存更改。关闭时有未保存内容会提示，保存失败保留草稿，保存期间编辑锁定。
5. 同步标准方案统一进入主备列表；流式、代理或特殊画廊方案标明“独立使用”，可设为当前方案，不参与同步 Images 自动切换。
6. 画廊主备池支持 **OpenAI 兼容、同步 Images API**；开启流式、代理或 Codex CLI 特殊模式后，该方案移出画廊主备池并使用原通道。Agent 的 Responses 流式请求仍可参与 Agent 主备。

| 情况 | 行为 |
| --- | --- |
| 主用成功 | 保存结果，记录实际使用方案 |
| 主用缺少 Key、地址/模型不完整 | 自动切换开启时跳过不完整方案，寻找可用备用 |
| HTTP 401/402/403/404/429 明确拒绝 | 自动切换开启时按顺序切换备用 |
| 超时、断线、服务器错误或结果状态不明 | 停止当前请求，不自动重复提交 |
| 成功响应开始后解析、下载或保存失败 | 不切换重发，防止重复计费 |
| 全部拒绝 | 显示失败；保留批量已保存图片 |

桌面画廊保留 5 分钟失败冷却，“最近调用结果”可查看受理记录、失败原因和清除冷却；修改连接配置也会清除该方案旧冷却。Agent 每次请求重新按自己的主备顺序选择，没有持久冷却。接口受理不等于图片已保存，最终以任务状态为准。

已有 Images / Responses 配置按协议归组，保留内容和密钥；没有 Responses 配置时需在 Agent 分组新建，不会把画廊密钥自动复制过去。导入的标准配置自动进入所属列表，主用与备用顺序可在同一列表管理。其他历史服务商记录保留供历史与备份使用，新设置页不再提供服务商切换、自定义服务商编辑、混合模式和配置 URL 分享入口。本地“复制一份配置”和数据导入导出保留。

## 收藏夹预览

“我的收藏”中，每个收藏夹用 2×2 四宫格展示最近加入的四张不同图片；不足四张时保留占位。同一作品加入不同收藏夹时分别记录时间，移除后重新收藏会排到前面。旧版本未记录加入时间的作品，按创建时间回退排序；升级后新增收藏使用真实加入时间。

## 获取和选择模型

1. 在 **API 配置 → 画廊 / Agent** 点开配置，填写地址和 Key，点击 **测试连通** 或 **获取模型**。两者均只读取模型目录，不发送生图或对话请求；成功时显示耗时与模型数量，并更新候选目录。使用当前编辑草稿检查，不会先保存或改变正在使用的连接。
2. **获取模型** 成功后弹出候选列表，默认勾选尚未添加的模型；**测试连通** 只显示结果。弹窗支持搜索、全选或取消全选当前结果，隐藏项保留勾选。点击 **添加所选** 合并到草稿，已有模型保留；取消或关闭不更改已启用列表。也可点击 **从已获取目录选择** 重开缓存目录，无需重复请求。已启用列表支持 **设为默认** 和 **移除**，至少保留一个模型；最后点击 **保存配置** 生效。
3. 服务不提供模型目录时，手动填写模型 ID，多个可用逗号分隔。获取失败保留原选择，区分鉴权失败、目录不支持、服务不可用和超时；连接修改后旧目录标记需刷新，旧请求不会覆盖新连接。模型目录可访问并不保证 Key 的全部权限或实际生成能力。
4. 画廊 **模型** 收起时仅显示模型名和简短服务商名称；点击打开选择面板，服务商名称及地址只在分组标题显示，模型行不重复地址，当前选项用勾选标记。超过四个已启用模型时显示搜索，支持搜索模型或服务商。上下方向键浏览、Enter 选择、Escape 关闭；点击外部或滚动参数区也会关闭。相同模型 ID 在不同方案内分别显示，选择后同时切换对应方案及主用，保留各方案默认模型，选择随共享配置保存。停用或未填完整的方案不提供选项，获取目录里尚未启用的模型不自动加入。
5. 画廊选择 **自动** 时使用当前方案默认模型，主备可按各方案默认模型切换；明确选择模型后，备用只尝试已启用同一 ID 的方案。正在执行的任务保留提交时所选模型。创作中的直接生成、Agent 生图及回复下的手动生图统一使用生图参数中所选图像模型；选择“自动”使用方案默认模型。历史复用填入草稿，使用当前图像配置；对话模型独立选择。
6. 获取目录不代表能力已验证。模型能力可按供应商说明设置看图、工具调用和是否支持推理参数。未确认看图支持时只传图片引用和文字。已标记不支持工具的模型仍能聊天，可通过回复下的手动生图入口使用画廊。
7. 点击 **保存配置**，目录、启用项、默认值与能力随配置保存。

## 对话创作与图片联动

“习惯配置”按外观、输入、图像生成、下载与通知、对话习惯分组。在“对话习惯”设置新对话默认模型、联网与自动滚动，工具调用上限和公式显示收在“高级偏好”中。已有对话独立记住模型、推理强度和联网；切换对话不会覆盖其他对话。

**绘图提示词优化** 位于 **设置与 API → 习惯配置 → 对话习惯**，默认开启。保存后对所有对话的下一次请求生效，也包含已有对话；正在进行的请求不变。开启后，AI 按从零生图、参考图创作或已有图片修改整理要求，明确每张参考图的用途、修改范围和保留项，并结合当前分支的历史与可用图片延续已确认要求、纠正可见偏差。具体需求只做整理，不随意添加人物、物品或无关风格。

例如，可以说“只把外套改成红色，保留脸、姿势、面料和背景”，或“图一参考人物，图二只参考画风”。想先检查完整提示词时点击 **只优化提示词**，这一步不会生图；关闭增强开关后，该按钮仍可进行普通改写。**直接生成** 和回复下的 **按此提示词生图** 直接提交已有文字，不经过这套对话优化。看图与结果纠偏取决于对话模型的图片理解能力，精确局部修改可配合蒙版；开启优化不增加独立的模型请求，但会增加每次对话的指令长度。

它与“图像生成”中的 **允许模型优化提示词** 独立：本开关控制对话助手如何整理绘图需求；后者控制提交给图像服务时是否附带尽量保留原文的要求。

| 操作 | 使用方式 |
| --- | --- |
| 普通聊天 | 选择对话模型后发送；支持拖入图片或用 `@` 引用，图片理解需确认模型支持看图 |
| 聊天生图 | 直接明确要求生成或修改图片，默认调用画廊；普通讨论、引用示例和明确“不要生成”要求只回复文字；无需再为 Agent 配置图像模型 |
| 生成参数 | 使用当前对话左侧参数栏（窄屏为抽屉）中的参数，模型返回的尺寸等参数不覆盖控件选择；结果卡显示实际模型、方案及参数 |
| 连续改图 | 结果卡点击 **继续修改**，自动带入图片引用；点击 **蒙版修改** 打开已有蒙版编辑器 |
| 历史复用 | **加入当前参考** 追加所选图片；**在当前对话修改 / 蒙版修改** 设置当前编辑目标；**复用提示词与参数** 替换草稿并可撤销；只有 **打开原对话** 切换到旧会话 |
| 手动生图 | 回复下点击 **按此提示词生图**，将该段回复直接交给画廊；点击 **填入输入框** 可先修改提示词与参数 |
| 失败后续写 | 聊天失败且已有图片任务时，“继续回复”保留图片并关闭本次新生图，避免重复提交；图片失败显示在任务卡 |
| 停止 | 终止本地后续处理及界面持有的对应任务；已受理的远端请求可能继续。独立 Codex 调用不受影响 |

未配置 API 时也可以直接进入创作页，不弹配置确认框。Agent 输入区始终保留“发送”按钮；缺少可用 Agent API，或所选模型不可用时，点击后进入 Agent 配置，具体原因在输入区提示。回复期间按钮切换为“停止”。

连续工具调用上限默认为 1，生图后不自动迭代；可在“设置与 API → 习惯配置 → 对话习惯 → 高级偏好”手动调高。旧版保存的上限也会重置为 1；更新后手动设置的新上限会正常保留。

模型、推理强度和联网选项在回复期间锁定。批量任务可保留部分成功结果。联网使用 Responses 搜索工具，具体支持以所选供应商为准；图像执行使用画廊 Images 配置，聊天与图像服务可以来自不同供应商。

推理强度位于 **模型后面、联网前面**，“默认”不发送覆盖参数。能力未知时允许手动选档；已知不支持时禁用，已知支持档位按能力列表展示。接口或备用方案拒绝所选强度会明确提示，不悄悄降低。旧 API 方案的强度不再覆盖当前对话。

创作页的对话记录与图片结果左右排列、独立滚动，输入区固定在左侧对话下方；可用 **左右分栏 / 展开对话 / 聚焦图片** 调整空间，切换不清空草稿。长文本自动增高后内部滚动。用户消息靠右，Agent 正文左对齐，消息流中保留图片任务状态和详情入口；图片本身在右侧按轮次比较。

## 上下文、历史与排错

- 输入区上方的 **当前上下文** 显示当前分支的历史轮次和可引用图片数（去重，包含当前附件），不是实际发送数量或计费用量。展开后勾选图片，点击 **携带图片新开对话**，只把所选图片、图像参数和对话偏好带到新对话；旧对话与草稿保留，操作本身不请求 API。原蒙版、旧聊天文字和提示词不会自动带入。生成中请先停止；读取期间切换对话或修改草稿会中止本次应用。
- **生成历史** 每页显示 60 条，底部可翻页。搜索、状态和收藏筛选仍覆盖全部历史；筛选改变回到第一页。跨页选择保留，批量操作前检查已选数量；框选只作用于当前显示的卡片。
- 在 **设置与 API → API 配置** 展开一套配置，查看本地必填项、模型目录和历史生图记录。获取目录遇到鉴权、限流、目录不兼容、超时或网络问题时，会给出下一步建议。历史记录不验证当前修改后的配置；对话、看图、联网和工具能力分别以实际调用结果为准。状态面板不自动发送收费请求。
- **数据管理 → 存储与备份状态** 显示当前入口、浏览器可提供的站点占用估算，以及最近一次全部 ZIP 分片已发起下载的时间、范围和数量。占用可能包含站点缓存，不包含项目配置、CLI 输出与自定义目录中的提示词数据；环境不支持时显示未知。导出记录不等于文件已落盘，请在下载目录确认全部分片。导出中途失败保留上一次记录。

## 批量生图与模型参数

- 同步批次最多同时执行两张，每张完成即保存并显示。点击“停止”后，已经完成的图片保留在当前结果和历史中；保存失败会停止后续投递，并继续尝试保存其他已在途结果。
- 普通网页按当前页面限流，桌面和本机网页按同一桌面实例限流；独立 CLI 按每次批次限流，不提供跨独立进程的全局限制。CLI 可用 `--concurrency 1` 改为串行，fal 和自定义异步接口保留原生批次。
- **设置与 API → 画廊 API 配置 → 选择配置 → 图像模型参数限制**：按服务商说明填写尺寸、质量、格式、原生透明和参考图上限。留空使用通用规则，0 张参考图表示不支持参考图。保存后参数区自动适配，请求前再次校验；参考图不会因切换模型而删除，对话仍可使用附件。
- 模型目录通常不提供完整能力说明，不会通过收费生成探测。停止本地请求不保证远端停止；超时或状态不明不自动重复提交。

## 个人提示词与作品备份

点击左侧独立的 **提示词库**，顶部横向切换栏首先是 **个人提示词**（首次打开时加入三个展示示例，删除后不再自动恢复），“网络提示词库”分隔标识后是 **水仙、PromptFill、YouMind、PixtoAI、NanoPrompts GPT-2、NanoPrompts、HeroPrompt**。每个网站内容区标题下显示可点击的官网首页地址。网站库名称与分类分区显示：顶部横向选择库，左侧独立竖向分类，右侧搜索与多列图片卡片；个人库使用完整内容宽度。窄屏使用紧凑的横向库标签，点击“选择分类”展开竖向列表，选中后收起。可直接浏览这些网站的在线内容，按分类筛选或搜索名称、正文，每页 24 条。点击卡片打开大图详情，图片完整显示并支持 **放大预览**，完整正文独立滚动；**一键使用** 只填入当前草稿，保留参考图与参数并可撤销，不会自动生成或上传网站预览图。网站正文中的变量占位可在草稿中按需修改。

点击 **收藏** 将正文、预览图链接和来源链接保存在 **个人提示词**，重复点击不会重复保存。编辑收藏保留来源信息；删除后可以重新收藏。收藏正文可离线使用；预览图优先读取已经预载的本地图片，未预载时联网加载，均不加入作品库。完整备份包含收藏正文及链接，不包含网络库目录和预载图片。

各网站目录和正文首次载入后分别自动保存在当前入口，重开应用复用，直到手动 **刷新**。刷新重新获取网站目录，保留已有图片；失败保留原目录。**全部分类 → 预载全部** 先提示确认，再下载全库预览图；其他分类点 **预载当前分类** 只下载该分类。预载范围不受搜索关键词和当前页影响，显示进度、失败数并可取消，已保存的图片会跳过，重试补齐缺失图片。切换页面可继续预载，关闭应用会中断，重新打开后可再次预载续补。

**清除预载数据** 二次确认后仅清除当前选中网站的全部目录、正文和预览图（包括其他分类），不删除个人提示词及收藏正文；收藏预览可从其他网站的同图缓存读取，否则恢复联网加载。清除后不会自动重复下载，点击刷新再载入。图片预载需要桌面或本机网页入口，复用现有本机连接读取这些网站的公开图床；普通网页入口可能受图床跨域限制。未设置自定义保存位置时，缓存按浏览器/应用入口分别保存，切换地址或端口不能共用，浏览器清理站点数据或回收空间可能移除缓存。启用自定义目录后，同一本机部署的桌面与本机网页读取同一提示词目录；清除网络库前会保留个人收藏已预载的图片。

所有站点共用浏览和操作布局，各自保存目录、更新时间、预载进度及图片缓存。水仙沿用原目录和收藏；PromptFill 仅收录图片模板，按标签分类（同一条可在多个分类出现），使用已选变量或默认值填入正文，仍未解析的占位符可在草稿中修改。PromptFill 没有稳定的模板详情网址，来源链接打开其探索首页，收藏用模板标识区分不同条目。

YouMind 首次读取或刷新需通过桌面或本机网页入口逐页加载，显示目录进度，完成后一次替换缓存；后续打开无需重复请求。收录 Nano Banana Pro 专题，优先使用网站提供的中文正文，否则保留原文，并填入参数默认值。网站公开接口没有逐条主题分类，当前按 **需要参考图 / 无需参考图** 分组，来源链接可打开具体条目。显示数量以实际可用记录为准，可能少于网站宣传总数。

所有网络库的操作区均有 **删除提示词库**。二次确认后移除网站入口，清除该库所有分类的目录、正文和预载图片；其他库、个人提示词及已收藏正文保留。删除状态随当前提示词存储跨重启保存，不会因更新重新加入。顶部右侧 **已删除的库** 可恢复入口，恢复后点击刷新重新获取数据，旧缓存不恢复。正在载入或预载时先完成/取消操作再删除；清除数据或保存删除状态失败时会显示错误。来源列表横向滚动，分类区单独竖向滚动；恢复库菜单浮层展开，不挤占内容区。

输入区 **提示词库** 打开同一独立页面；点 **保存提示词** 直接打开当前草稿的保存表单。页面顶部也可 **保存当前草稿** 或 **新建提示词**，填写名称与正文。个人卡片详情中可编辑或删除。提示词库支持中文搜索、编辑、删除及一次撤销删除。**一键使用** 只替换文字，保留参考图和参数；替换后可撤销，继续编辑或切换会话后不再恢复旧草稿。

### 自定义提示词库保存位置

进入 **设置与 API → 数据管理 → 提示词库保存位置**。桌面可选择文件夹，本机网页可填写完整路径，然后点击 **复制并使用新位置**；此设置立即生效，无需点击“保存配置”。普通网页入口继续使用浏览器存储。

所选文件夹下会建立独立的 `提示词库` 子目录，包括所有已经保存的网络提示词库、个人提示词、收藏及预载图片：

```text
提示词库/
  个人提示词/
    目录.json
    图片索引.json
    未分类--标识/
      提示词.json
  水仙/
    目录.json
    图片索引.json
    分类名称--标识/
      提示词.json
      图片/
  其他已保存的网络库/
  偏好.json
```

每库的 `目录.json` 保存完整正文、名称、标签、来源、图片链接和更新时间；分类文件方便查看，图片按主分类保存，其他标签保留在属性中。分类名称中的非法文件名字符会替换，并附短标识避免重名。无分类的个人提示词放在“未分类”。这些文件由应用维护，手工修改分类文件不会反向导入应用。

更换位置先复制并校验，成功后才切换；默认保留旧位置及旧浏览器缓存，非空目标不会被覆盖。已有文件目录再次迁移时，可勾选“迁移成功后清理原位置文件”，确认框会列出新旧位置。仅清理已登记的提示词、属性和图片，优先移入回收站；用户自行放入的其他文件留在原位置。清理失败不影响新位置使用，界面会提示原目录可能有残留。首次从应用内存储迁入文件夹不清理浏览器数据，也不会自动追溯删除之前保留的副本。复制期间有其他窗口保存时会拒绝切换，请重新尝试；旧窗口随后修改会提示重新打开。迁移只复制已有图片，不自动下载未预载图片。启用目录后，个人增删改、收藏、导入与清空都会写入该目录；保存失败保留原个人库与编辑内容。目录暂时不可用时恢复访问后重新打开工具，不会自动用浏览器旧副本覆盖文件。

保存位置配置保留在本机用户目录，作品、对话及 API 配置位置不变。文件存储不提供多设备并发同步；网络盘应在可访问时使用。备份全部提示词库时，停止提示词操作后复制整个 `提示词库` 文件夹；下面的 ZIP 备份仍只包含个人提示词正文及链接，不包含网络目录和预载图片。

数据管理中勾选 **包含作品、对话和个人提示词**，可一并导出或导入个人提示词。旧备份没有个人库时保留现有条目；同 ID 同内容去重，内容冲突保留两份。清除这一选项会一起清除作品、对话和个人提示词；仅清配置不删除个人库。

创作对话只增量保存改动的会话，流式回复约每 300 毫秒合并写入，完成或停止时立即请求保存。保存失败时界面显示 **重试保存对话**，内容仍保留在当前窗口；正常完成以数据库事务提交为准，强制关闭进程仍可能丢失尚未提交的末尾内容。手动重试图片在当前会话建立新轮次，保留原任务；本地保存失败不会自动再请求生图。

## 配置保存与 Codex 调用

- 换过电脑或 Windows 账户后，项目中的旧加密配置可能无法解密。启动页会说明原因并暂停自动保存和生图；可以回到原电脑及账户使用，或点击 **保留旧配置并重新配置**。点击后，原文件原样保留为 `user-config/desktop-settings.unreadable-随机标识.json`，建立空 Key 的新配置并重新打开工作区；需要在设置中重新填写地址、Key 和模型。历史与作品不清空；恢复写入失败会还原旧配置。同一份配置已被其他窗口更新时，会拒绝恢复，请重新打开工具。
- 桌面、本地网页和 Codex 共用同一份设置，包括两组 API、主备、模型和使用习惯。设置页修改为草稿，点击保存后才生效。Key 使用当前 Windows 用户的 DPAPI 加密；共享配置保存在项目 `user-config/` 文件夹，排除 Git。完整设置使用 `desktop-settings.json`，旧网页同步快照使用 `codex-profile.json`。启动时自动创建配置文件夹，保存设置后生成配置文件。
- 桌面和本地网页不把完整设置再写入网页 localStorage；旧浏览器配置仅在本机尚无共享设置时采用。已有共享设置优先，打开新浏览器不会覆盖它。保存失败保留草稿，加载失败阻止覆盖已有配置。
- **任一入口保存成功后 Codex 直接读取；其他已打开的桌面/本地网页约 5 秒内更新。** 同时编辑时旧草稿的保存会被拒绝，避免覆盖另一窗口的新配置；关闭设置后重新打开，再应用修改。作品、历史和对话仍保存在各自本机 WebView/浏览器存储中，此次共享范围是配置。
- Codex 使用画廊主备池，通过独立的 `scripts/playground_image.py` / `run-image.cmd`，不需要桌面保持打开。标准 Images 的本地网页请求也使用同一执行器和主备规则。
- 关闭桌面窗口会停止本窗口的本地服务和它发起的生图子进程。Codex 单独启动的调用不属于它，不随窗口关闭。关闭正在生成的窗口不代表服务商已取消或退款。
- 命令行默认图片输出保存在当前电脑用户目录的项目数据区；JSON 返回实际绝对路径。可用 `--output` 明确选择导出位置，不自动进入桌面历史。
- 统一 CLI 为 `chat-to-image.cmd`，生成/编辑复用现有执行器。通过 **设置与 API → Agent 连接** 可连接 Codex、Claude Code、Cursor、DeepSeek Harness，查看本机状态、更新或断开。连接操作立即生效，重新打开 Agent 会话读取；接入文件就绪不代表真实调用已验证。
- DeepSeek Harness 使用专属 `.dsh/skills/chat-to-image-cli`；设置了绝对路径 `DSH_HOME` 时使用其 `skills` 目录。命令行目标为 `deepseek-harness`，例如 `chat-to-image.cmd agents connect --target deepseek-harness`。自定义 Harness 配置需启用本地技能发现；详细目录与共享技能说明见 [调用接口文档](docs/codex-image-interface.md#3-在-codex-中使用)。
- **手动调用命令** 由当前运行的项目位置自动生成，只调用 `chat-to-image.cmd`；启动脚本在当前电脑寻找 Python，CLI 默认读取当前项目配置，命令不绑定 Python 安装路径或配置目录。换电脑或移动项目后重新打开连接页，复制新命令；新电脑仍需填写自己的 API 配置。
- 新 `chat-to-image-cli` 接入只提供完整本机命令及 `agent-guide` 引导，完整说明随程序更新；不依赖 `PLAYGROUND_PROJECT_ROOT`，不改变全局默认生图偏好。更新/断开前备份，个人修改和其他项目接入受到保护，其他文件保留。普通网页提供 CLI 说明，连接管理在桌面操作。
- 这是本地 CLI 调用接口，**当前没有注册 MCP 服务**。完整命令、连接目录及错误处理见 [Codex 接口说明](docs/codex-image-interface.md)。

只检查配置，不读 Key、不联网：

```powershell
python -B scripts/playground_image.py --prompt "一只纸飞机" --dry-run
```

实际生成：

```powershell
.\run-image.cmd --prompt "白色背景上的橙色纸飞机" --size 1k
```

已有同名输出不会覆盖。地址只填写接口地址，凭据只填写 Key 字段，不把 Key 放进 URL、导出文件或截图。

## 更换电脑或移动项目

开发期间修改代码和构建保留用户已填写的 `user-config/`，不因更新清空配置或本机历史，方便持续测试。开发完毕后的个人配置由用户自行删除；复制工具到其他电脑时仍按以下规则跳过配置与用户备份。

1. 复制工具目录中的源码、启动文件和 `dist/`，跳过 `user-config/` 及用户自行导出的备份，不附带 API 密钥、历史或作品。只有共享配置放在项目文件夹，其他用户数据仍在本机。
2. 新电脑安装 Python 3.10+，双击 `run-app.cmd`。没有配置时自动创建项目配置文件夹和本机运行目录，显示空白工作区。桌面依赖安装到专用运行环境；WebView2 以启动提示为准。
3. 运行时自动登记当前项目位置；历史、作品、浏览器档案、日志和运行环境位于当前 Windows 用户的本机应用数据区，按项目隔离。移动工具目录不会自动搬运这些数据。
4. 新电脑重新填写 API 和 Key。`user-config/` 中的凭据仍绑定原 Windows 账户，复制配置文件不能保证在另一电脑解密；项目同步不等于跨设备配置共享。
5. 若用户另行决定迁移作品，可自行导出/导入备份；备份独立存放，不随工具复制。桌面历史位于该设备 WebView 的 IndexedDB，浏览器历史位于该浏览器的本机存储。
   恢复 Web 桌面后会继续使用原有的 WebView 来源和本机档案。Qt 阶段的原生作品库保留在原位置，不会自动迁入或删除。
6. 在新电脑打开桌面“设置与 API → Agent 连接”，重新选择要连接的 Agent，再打开新的 Agent 会话。移动项目前先在旧位置断开；新位置重新连接以更新本机命令路径。旧的 `generate-playground-image` 已卸载。

## 本地浏览器入口

双击 `run-sync.cmd`，它启动/复用本机网页服务并打开浏览器。已有共享配置直接读取；尚无配置时，在网页填写并保存。成功后服务保留在后台，生命周期与桌面窗口独立。旧版后台服务需先关闭其所属启动窗口，再运行更新后的入口。

需要保留启动窗口用于停服时，运行 `run-sync.cmd --stay-open`。按 Ctrl+C 会正常停止本窗口启动的服务及其生成任务，并清理临时文件；复用的服务和独立 Codex 调用继续运行。

网页保存与桌面保存都更新同一份本机加密配置，无需重新同步当前单套 API。独立部署的静态网页仍使用自己的浏览器存储；三端共享请使用本工具的桌面或本地浏览器入口。

## 常见问题

- **参考图提示图片容器不完整**：更新后的工具支持结束标记后带附加数据的 JPEG。关闭并重新打开桌面窗口，再重试该任务；错误提示会区分参考图、蒙版与接口返回的图片。历史失败记录保留原提示，不代表修复后的再次运行结果。
- **重复启动或端口占用**：窗口会给出错误，不会杀掉其他程序。已有窗口从任务栏切回；端口被其他程序占用时先识别该程序。桌面固定自身本机来源，以保留历史。
- **Agent 或流式请求跨域错误**：这些请求由页面直接发出，需要服务商允许跨域。标准桌面同步 Images 请求由 Python 发出。
- **关闭后结果不确定**：查看服务商记录再决定是否重新生成，避免重复收费。
- **设置未生效**：先看侧栏是否显示保存失败；重试成功后再次执行 Codex 预检查。
- **构建或依赖失败**：错误提示会保留，先检查 Python、Node/npm 和网络，再重试。不要手工修改 `dist/`。
