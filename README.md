# Chat to image

在 Windows 本机运行的 AI 图片生成与编辑工具，将直接生图、对话式创作、提示词管理和作品整理放在同一个工作区。支持桌面窗口、本地浏览器及独立 CLI 调用，通过用户配置的 OpenAI 兼容 API 使用图像和对话模型。

本项目独立维护，当前版本 **0.1.0**。项目地址：[Kenrohoro-hub/Chat-to-image](https://github.com/Kenrohoro-hub/Chat-to-image)。详细操作见 [中文使用说明](README_使用说明.md)。

## 主要功能

| 功能 | 当前支持 |
| --- | --- |
| 图片生成与编辑 | 文字生图、参考图、蒙版局部修改、多图生成、连续改图；尺寸、比例、质量、格式与透明背景按接口能力设置。 |
| 对话式创作 | 讨论构图、优化提示词、按要求生成或修改图片；支持图片引用、对话分支、停止回复及可选联网。 |
| API 与模型管理 | Images 图像接口与 Responses 对话接口独立配置，各组最多 10 套；获取模型、启用模型、指定默认模型、主备排序与自动切换。 |
| 个人提示词 | 新建、编辑、搜索、收藏、删除及撤销，主题分类可创建、重命名和删除；将提示词填入创作草稿，保留参考图和参数。 |
| 网络提示词库 | 浏览七个网络库，支持分类、搜索、图片详情、收藏、一键使用、目录缓存、图片预载、删除及恢复入口。 |
| 提示词文件保存 | 可指定本机保存位置，按库名和分类保存正文、来源及已预载图片；切换位置先复制校验，再启用，保留旧数据。 |
| 作品与对话管理 | 历史搜索、收藏、图片下载、参考图复用、对话管理，以及作品、对话和个人提示词的导入导出。 |
| 外部 Agent 接入 | 通过本地 CLI 接入 Codex、Claude Code、Cursor 和 DeepSeek Harness，生成或编辑图片后返回本地路径。 |
| 使用体验 | 中文界面、深浅主题、可折叠侧栏、窄屏布局及设置保存反馈。 |

## 快速开始

### 运行前提

| 环境 | 用途 |
| --- | --- |
| Windows 与 WebView2 运行时 | 桌面窗口和本机加密配置。 |
| Python 3.10 或更新版本 | 桌面启动、本机服务和 CLI。 |
| 当前受支持的 Node.js LTS，包含 npm | 从源码安装前端依赖和构建；已有完整 `dist/` 时，日常启动不需要 Node。 |
| 可用的 API 地址、Key 和模型 | 用户自行提供；本项目不附带模型服务或调用额度。 |
| 网络连接 | 首次安装依赖、调用 API，以及首次读取或刷新网络提示词。 |

### 从源码启动

1. 下载完整源码并解压，或克隆仓库：

   ```powershell
   git clone https://github.com/Kenrohoro-hub/Chat-to-image.git
   cd Chat-to-image
   ```

2. 双击项目根目录的 `build-app.cmd`，或在该目录运行：

   ```powershell
   .\build-app.cmd
   ```

   脚本在本机缓存目录安装依赖并构建，再更新项目 `dist/`，支持网络共享路径。

3. 双击 `run-app.cmd` 打开桌面窗口。首次启动会在本机用户目录建立专用 Python 环境，并安装桌面组件；失败会显示错误提示。
4. 打开左下角 **设置与 API → API 配置**，填写图像或对话服务，点击 **保存配置**。
5. 直接生图只需要画廊 Images 配置；对话式创作还需要 Agent Responses 配置。

**GitHub 自动生成的源码 ZIP 不包含被 Git 忽略的 `dist/`。首次使用源码必须先构建，不能直接双击桌面启动。** 更新源码后，先关闭应用，再重新运行 `build-app.cmd`。

### 使用本地浏览器

已有构建文件后，双击 `run-sync.cmd`。它启动或复用本机服务并打开浏览器，与桌面和 CLI 共用 API 设置。

需要保留控制台以便停止服务时，运行：

```powershell
.\run-sync.cmd --stay-open
```

按 Ctrl+C 停止该入口创建的服务及任务。桌面和浏览器的作品、历史与对话存储分别独立；共用 API 设置不代表共用全部作品数据。

在 **设置与 API → 功能介绍** 可查看当前版本、主要功能、快速使用步骤与项目主页。

## 配置与创作

- **画廊 · Images**：填写图像模型，支持直接生图、参考图编辑和蒙版修改。
- **Agent · Responses**：填写对话模型，负责文字讨论和提示词优化；需要生图时使用画廊配置。
- 两组 API 的主用、启停、备用顺序及自动切换开关分别管理，修改后需保存才能生效。
- 获取模型目录后，可以选择启用项和默认模型；服务不提供目录时可手动填写模型 ID。
- 主备切换只在明确拒绝或本地配置不完整等可识别情况启用。超时、断线或受理结果不明时，不自动重复提交同一生图任务。
- 历史复用只填入草稿，便于检查后再提交；网络提示词的“一键使用”也不会自动生图。

图片理解、联网、推理强度、流式返回、透明背景及编辑参数是否可用，取决于所选模型和服务商。模型目录可读取不等于全部能力已验证。

## 提示词库

当前网络来源如下：

| 来源 | 内容 |
| --- | --- |
| [水仙](https://prompt.qqsrc.com/) | 分类图片提示词。 |
| [PromptFill](https://promptfill.tanshilong.com/explore) | 带选项和变量的图片模板。 |
| [YouMind](https://youmind.com/zh-CN/nano-banana-pro-prompts) | Nano Banana Pro 专题。 |
| [PixtoAI](https://www.pixtoai.com/styles/) | 图片风格提示词。 |
| [NanoPrompts GPT-2](https://nanoprompts.org/zh/gpt-image-2) | GPT-image-2 专题。 |
| [NanoPrompts](https://nanoprompts.org/zh) | Nano Banana 专题。 |
| [HeroPrompt](https://heroprompt.sortes.ai/zh) | 多语言提示词。 |

目录首次读取后保存，重开优先复用；手动刷新失败时保留已有目录。可预载当前分类或全部分类的图片，支持进度、取消和再次补齐。删除网络库需确认，其他库和个人收藏保留；恢复入口后需刷新重新获取。

进入 **设置与 API → 数据管理 → 提示词库保存位置**，选择文件夹或填写完整路径，再点击 **复制并使用新位置**。应用在该位置下建立独立的 `提示词库` 子目录，保存个人提示词、网络库、分类属性和已有预载图片。迁移不会自动下载尚未预载的图片，非空目标不会被覆盖。

默认使用浏览器本地存储；启用文件目录后，同一本机部署的桌面与本机网页读取同一提示词目录。文件模式不提供多设备并发同步，手工修改分类文件也不会反向导入应用。

## 外部 Agent 与命令行

桌面 **设置与 API → Agent 连接** 提供连接、检查、更新与断开操作，支持 Codex、Claude Code、Cursor 和 DeepSeek Harness。连接后重新打开相应 Agent 会话，让它读取接入文件。

也可以在项目根目录运行：

```powershell
.\chat-to-image.cmd doctor
.\chat-to-image.cmd agent-guide
.\chat-to-image.cmd agents status
```

`doctor` 检查本地运行环境和脱敏配置，不联网验证 Key。`agent-guide` 读取本项目随附的调用说明。生成与编辑参数见 [CLI 接口文档](docs/codex-image-interface.md)。

CLI 使用画廊的标准同步 Images 配置，可以在桌面关闭后独立调用；结果默认保存在本机用户数据区，不会自动加入桌面历史。当前接入方式是本地 CLI，未注册 MCP 服务。

## 数据与个人设置

| 数据 | 保存方式 |
| --- | --- |
| API 设置、模型、主备与使用习惯 | 项目 `user-config/` 内的共享配置，使用当前 Windows 用户的 DPAPI 加密保护；已被 Git 忽略。 |
| 桌面作品、历史、对话及运行数据 | 本机 Windows 用户数据区；桌面 WebView 和不同浏览器的站点存储分别保存。 |
| 提示词目录与预载图片 | 默认在当前入口的浏览器存储；启用自定义位置后保存到所选目录。 |
| CLI 图片输出 | 默认在本机用户数据区，也可通过参数指定导出位置。 |
| 手动导出的备份 | 保存在用户选择的位置，独立于程序源码。 |

生成和对话会将相应提示词、消息及参考图发送给用户配置的 API；网络提示词读取和图片预载会访问对应网站。界面和数据在本机保存，不意味着模型在本机推理。

正常通过 Git 上传源码不需要删除个人设置。`user-config/`、本地环境配置和默认 `outputs/` 已排除；手动 ZIP 打包需要另外排除这些目录及个人备份。自定义提示词目录建议放在项目之外，放入项目内的导出数据不一定受现有忽略规则保护。

更换电脑或 Windows 账户后应重新填写 API Key，原账户的加密文件不能保证在新环境解密。移动程序目录不会自动搬运作品和历史；需要迁移时使用应用的数据导出与导入功能。

恢复 Web 桌面后会继续使用原有的 WebView 来源和本机档案。Qt 阶段的原生作品库保留在原位置，不会自动迁入或删除。

作品备份可包含作品、对话及个人提示词正文和链接，但不包含全部网络目录和预载图片。备份完整提示词文件库时，停止相关操作后复制整个 `提示词库` 文件夹。

## 开发与检查

前端使用 React 19、TypeScript、Vite、Zustand 和 Tailwind CSS；桌面与本机服务使用 Python，桌面窗口由 pywebview 与 WebView2 提供。

| 命令 | 用途 |
| --- | --- |
| `build-app.cmd` | 在本机缓存目录安装前端依赖、构建并更新项目 `dist/`。 |
| `build-app.cmd --test` | 在本机缓存目录运行前端测试，适用于网络共享路径。 |
| `npm ci` | 根据锁文件安装前端依赖。 |
| `npm run dev` | 启动前端开发服务器；普通开发页面不等同于桌面或本机共享服务。 |
| `npm run build` | TypeScript 检查及 Vite 构建，输出 `dist/`。 |
| `npm test` | 运行 Vitest 前端测试。 |
| `npm run mock:api` | 启动本机故障模拟 API，说明见 [模拟 API 文档](docs/mock-image-api.md)。 |

前端源码位于 `src/`，本机服务和 CLI 位于 `scripts/`，构建输出位于 `dist/`。不要手工修改构建文件。项目使用 npm，不使用 yarn 或 pnpm。
